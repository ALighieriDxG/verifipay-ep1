03 — Por qué agente + LLM + RAG

Cada pieza cubre un fallo distinto del soporte.

RAG

Dato verificable

Plazos, comisiones y normas viven en documentos. El modelo recupera el fragmento y responde con esa evidencia, en lugar de recordar de memoria (Lewis et al., 2020).

LLM

Lenguaje natural

El comercio no escribe una consulta SQL. El modelo entiende la pregunta y redacta una respuesta clara, en español, a partir del contexto recuperado.

Agente

Elige la herramienta

No toda pregunta va al mismo sitio. El agente decide entre documentación interna, normativa externa o la API mock de transacciones.

Corpus interno

Manual, políticas, FAQ, glosario y tickets resueltos. Operación y comercio.

Corpus externo + API

Ley 19.628, CMF y PCI-DSS, más tres transacciones simuladas (TX-20250908-001, 002 y 015).

04 — Prompts · IE2

El prompt acota el rol y obliga a citar.

  • 01Rol fijo: agente de soporte de comercios VerifiPay.
  • 02Usar herramienta antes de informar plazos, comisiones o normas.
  • 03Cerrar con la fuente: archivo o identificador de transacción.
  • 04No inventar cifras. No pedir RUT, PAN ni CVV.
  • 05Si no hay evidencia, escalar. No completar el vacío.

Temperatura 0,1. El FAQ funciona como ejemplo de pregunta–respuesta para la recuperación.

Enrutamiento por herramienta

El modelo elige, no un if rígido

buscar_documentacion_interna
Procedimientos, comisiones, errores, FAQ.

buscar_normativa_externa
Datos personales, PCI-DSS, CMF.

consultar_estado_transaccion
Estado real simulado, por ID.
